## 2. Исправленная версия ТЗ

### Функционал корзины

1. Пользователь может добавить в корзину от 1 до 10 единиц одного товара.
2. Пользователь может изменить количество товара в корзине в диапазоне от 1 до 10 единиц.
3. Для удаления товара используется отдельная кнопка **«Удалить»**.
4. В корзине может находиться не более 5 различных товаров.
5. Суммарное количество всех товаров в корзине не может превышать 20 единиц.
6. При попытке превысить установленные ограничения система отображает сообщение: **«Лимит корзины превышен»**.
7. Цена товара фиксируется на момент добавления в корзину и не изменяется до оформления заказа либо удаления товара из корзины.
8. На странице корзины отображаются:
   - наименование товара;
   - количество;
   - цена за единицу;
   - стоимость позиции;
   - итоговая стоимость корзины.
9. Товары в корзине могут относиться к различным категориям.
10. В корзине может отображаться рекламный блок с рекомендациями товаров.
11. Рекламный блок отображается по будним дням с 08:00 до 11:00 и с 18:00 до 21:00 по местному времени пользователя.
12. При удалении товар полностью исключается из корзины.
13. Изменение цены товара в каталоге не влияет на цену товара, уже добавленного в корзину.

## Назначение

Получение списка партнерских магазинов для отображения на экране выбора магазина в мобильном приложении.

---

## REST API

### Запрос

```http
GET /api/v1/partner-stores
```

### Заголовки

| Заголовок | Обязательный | Описание |
|------------|------------|------------|
| Authorization | Да | Bearer Token пользователя |
| Accept | Нет | Ожидаемый формат ответа (`application/json`) |

Пример:

```http
Authorization: Bearer <token>
Accept: application/json
```

## Описание полей ответа

### Store

| Поле | Тип | Описание |
|--------|--------|--------|
| id | string | Идентификатор магазина |
| name | string | Наименование магазина |
| deliveryType | string | Тип доставки (`scheduled`, `express`) |
| deliveryText | string | Текст отображения доставки |
| logoUrl | string | Ссылка на логотип магазина |
| externalUrl | string | Ссылка для перехода на внешний ресурс |

---

## Возможные ответы

| Код | Описание |
|--------|--------|
| 200 OK | Список магазинов успешно получен |
| 401 Unauthorized | Пользователь не авторизован |
| 500 Internal Server Error | Внутренняя ошибка сервера |

---

## Логика работы

1. Пользователь открывает экран выбора магазина.
2. Мобильное приложение вызывает `GET /api/v1/partner-stores`.
3. Backend возвращает список партнерских магазинов.
4. При нажатии на карточку магазина мобильное приложение выполняет переход по ссылке из поля `externalUrl`.

# Задание 3. Архитектура PUSH-уведомлений

## Диаграмма

![Архитектура PUSH-уведомлений](push-architecture.png)
## Описание решения

Для реализации PUSH-уведомлений используется отдельный сервис уведомлений.

Источниками событий являются:
- Сервис корзины (брошенная корзина);
- Сервис заказов (отмена заказа);
- Сервис маркетинга (рекламные рассылки).

Для фоновых сценариев используется планировщик, который запускает проверки неактивных корзин и рекламные рассылки по расписанию.

Все события публикуются в брокер сообщений Kafka/RabbitMQ. Сервис уведомлений получает события из брокера, формирует PUSH-уведомление и передает его в сервис доставки PUSH.

Сервис доставки PUSH отправляет уведомление в мобильное приложение пользователя.

## Основной сценарий работы

1. В системе возникает событие.
2. Событие публикуется в Kafka/RabbitMQ.
3. Сервис уведомлений получает событие.
4. Формируется PUSH-уведомление.
5. Уведомление передается в сервис доставки PUSH.
6. Пользователь получает уведомление в мобильном приложении.
